# Concept: Goal-Conditioned GPT-2 Pedestrian Trajectory Prediction

## Overview

This method trains a **GPT-2 autoregressive transformer** to predict the full path of a pedestrian agent from its spawn point to its exit goal, conditioned on:

- The **walkable geometry** of the environment (rooms + corridors as an occupancy grid)
- The agent's **start position** and **exit goal**
- The **observed motion** of nearby neighbours (social context)

The model learns purely from recorded pedestrian trajectories generated by a Social Force Model simulation — no hand-crafted physics or rules.

---

## What the Model Learns

### 1. Obstacle Avoidance
The geometry of each environment is encoded as a 64×64 binary occupancy grid (walkable = 1, wall = 0) using the same `unary_union(rooms + corridors)` logic as the simulator. A CNN (`GeoEncoder`) compresses this grid into a single embedding vector, giving the model a spatial "map" of where it is allowed to walk.

### 2. Goal-Directed Movement
The agent's normalised spawn position and exit centroid are concatenated and projected into the same embedding space. The model learns to steer trajectories toward the goal rather than wandering randomly.

### 3. Social Interaction (Collision Avoidance Between Agents)
The K = 10 nearest neighbours (by distance at observation time) each contribute a context token. Each neighbour's observed trajectory is encoded by a small `NeighborEncoder` (linear projection → mean pool → LayerNorm) into one d-dimensional token. These tokens are prepended to the GPT-2 input so the model can learn to slow down, detour, or yield when neighbours are close.

---

## Architecture

```
┌────────────────────── Context Prefix (prepended once) ──────────────────────┐
│  [geo + goal token]  [neighbour_1 token]  …  [neighbour_10 token]           │
└─────────────────────────────────────────────────────────────────────────────┘
                                    ↓
          GPT-2 Transformer  (128-dim, 4 heads, 4 layers)
                                    ↓
┌─────────────── Trajectory Sequence (causal / left-to-right) ───────────────┐
│  obs_1  obs_2  obs_3  obs_4  obs_5  →  pred_1  pred_2  …  pred_T           │
└─────────────────────────────────────────────────────────────────────────────┘
                                    ↓
                         Output Head  →  (x, y)
```

| Component | Role |
|-----------|------|
| `GeoEncoder` | CNN: occupancy grid [1,64,64] → embedding [d] |
| `cond_proj` | Linear: (start, goal) [4] → [d] |
| `context_fuse` | Linear: fuse geo + goal → single context token |
| `NeighborEncoder` | Per-step linear → mean pool → LayerNorm → [K, d] |
| `GPT2Model` | Causal self-attention over prefix + trajectory tokens |
| `output_head` | Linear: hidden [d] → (x, y) |

Total parameters: **~7.5 M**

## Training

**Mode: Teacher Forcing**

During training the ground-truth future trajectory is fed as input (shifted by one step), and the model predicts each next position simultaneously in a single forward pass. This is much faster than autoregressive training.

```
Input  = [context | obs_1..5 | pred_1..T-1]
Target =                       [pred_1..T  ]
Loss   = SmoothL1 (Huber), masked to ignore zero-padded positions
```

- Optimizer: AdamW (lr=3e-4, weight_decay=1e-4)
- Scheduler: ReduceLROnPlateau (patience=5, factor=0.5)
- Gradient clipping: max_norm=1.0
- AMP (fp16): enabled on CUDA for ~1.5–2× speedup
- `torch.compile`: enabled on CUDA for additional ~20% speedup

---

## Inference

**Mode: Autoregressive with KV-Cache**

At test time the model generates step-by-step. The context prefix and observed frames are processed once (prefill), then each new position is predicted one token at a time using cached key-value pairs — O(T) instead of O(T²).

```
[context | obs_1..5]  →  prefill  →  past_kv
past_kv  →  predict step 6
past_kv  →  predict step 7
…
past_kv  →  predict step T
```

## Data

| Item | Detail |
|------|--------|
| Dataset | `Dataset/Data_Traj_Table/Topo_bottleneck` |
| Simulations | 877 total (613 train / 175 test / 89 val) |
| Agents per sim | 100 |
| Frame rate | 25 fps recorded, sub-sampled with `frame_stride=8` → ~3 fps |
| Sequence length | ~50–450 steps after striding (max 512) |
| Coordinate space | Normalised [0, 1] via bounding box of walkable area |
| Observation seed | First 5 frames (`obs_len=5`) given as context |
| Prediction target | Remaining frames to destination |

---

## Evaluation Metrics

| Metric | Formula | Unit |
|--------|---------|------|
| **ADE** | Mean displacement error over all predicted steps | metres |
| **FDE** | Displacement error at the final predicted step | metres |

Metrics are computed in world coordinates (metres) by denormalising via `grid_to_world()`.
